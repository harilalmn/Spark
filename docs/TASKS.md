# Spark — Task Register

Every task, its epic, and its state. Epics are described in [EPICS.md](EPICS.md); priority
order for what to do next is in [TODO.md](TODO.md); the requirements behind them are in
[PRD.md](PRD.md).

**Last updated:** 2026-08-27
**Legend:** `Done` · `In progress` · `Open` · `Blocked` · `Withdrawn`

**Summary:** 29 done · 12 in progress · 201 open · 4 withdrawn

Twenty-nine done tasks, verified by reading the repository and running the gates rather than
by recollection: `dotnet build Spark.slnx --no-incremental -warnaserror` is clean,
`dotnet test Spark.slnx` runs **315 passing tests across four test projects**
(`Spark.Geometry.Tests` 276, `Spark.Geometry.Properties` 28, `Spark.Architecture.Tests` 6,
`Spark.Docs.Verify` 5), `dotnet format Spark.slnx --verify-no-changes --severity warn` is
clean, nineteen ADRs are written and indexed, and the lacing specification exists. All three
gates were run on Windows on 2026-08-27.

**Four tasks are `Withdrawn`, all four for one reason.** `E1-T24`, `E12-T6`, `E12-T7` and
`E12-T17` were about publishing Spark's own assemblies to nuget.org — reserving package IDs,
shipping the CLI as a dotnet global tool, packaging the contract projects, and settling
whether `Spark.Host` was among them. **D11** settles that Spark *consumes* NuGet packages and
publishes none, so none of the four has a job left to do. They are withdrawn rather than
deleted, with the reason on each row, because a task that vanishes silently is a task
somebody re-adds. The blocked count is now zero: the one blocked task was `E1-T24`, and it
was never unblockable — it was unnecessary.

**Twelve tasks are `In progress`.** Six of them are CI — `E1-T14` … `E1-T18` and `E11-T14`.
The workflow file is written and committed, and **it has never run on GitHub.** Written and
committed is not proven, and no CI task moves to `Done` on the strength of a file existing.
The other six — `E1-T12`, `E1-T25`, `E2-T1`, `E2-T33`, `E10-T8` and `E11-T10` — are genuinely
part-delivered, and each row says which part landed and which did not.

**Scope of this reconciliation.** This pass closes the E2 reconciliation the previous pass
deliberately deferred. The geometry kernel's **first slice — the value layer — has landed,
been reviewed, repaired and accepted.** `src/Spark.Geometry` holds thirteen types: `Angle`,
`Tolerance`, `Point3d`, `Vector3d`, `Point2d`, `Vector2d`, `UV`, `Interval`, `BoundingBox`,
`Plane`, `Transform`, `CoordinateSystem`, and an internal `NamespaceDoc` that carries the
namespace-wide conventions. Together they declare **387 public members**, every one of them
recorded in `src/Spark.Geometry/PublicAPI.Unshipped.txt`.

**The review is the important part of this entry, and it is recorded rather than tidied
away.** The first attempt at this slice **passed all three gates and was rejected**. An
independent review found three of its eight claims false — most damningly that
`default(Plane).Contains(anyPoint)` returned `true`, so every point in space silently lay on
the null plane. Both tests written to guard the type were **structurally incapable of
failing**: simulating the property's generator gave zero violations in five million draws
against CsCheck's hundred per run, where a generator that straddles the threshold finds 908
violations in 12,006 pairs. Gates are not review, and this project now has its own evidence
for that rather than somebody else's.

**The standard that came out of it, and that every subsequent kernel fix is held to: a fix is
regression-proven by reverting it and naming the test that goes red.** A fix with no test that
notices its absence is a fix that will be undone by the next refactor without anybody hearing
about it. That was the thing missing the first time round.

**No curve, surface, mesh or BRep task has moved**, because none of those types exist. Rows
below that describe them are the plan they have always been.

**Ten tasks are new, and all ten come from one exercise.** The client's instruction — *make
sure we have all geometry elements and methods and properties what is there in Dynamo* — has
been turned into a register, [DYNAMO-COVERAGE.md](DYNAMO-COVERAGE.md), built from a
metadata-only read of the `ProtoGeometry.dll` installed with Revit 2026: **51 public types and
837 public members**, of which **92 are reachable in Spark today — 11.0%**, or 16.0% of the
575 members we have actually committed to. `E2-T40` … `E2-T46` are one task per subsystem and
carry no detail of their own; the document is their detail. `E2-T47` and `E2-T48` are the two
decisions the exercise surfaced and neither is ours to make: **32 members cannot exist without
the exact solid booleans that PRD §9 currently puts post-1.0**, and **T-Splines is 169 members,
20.2% of the whole surface, and a subdivision modeller rather than a subsystem**. `E11-T23` is
the two-way diff test that stops the register becoming the next `DocGenerator` — 837
hand-maintained Markdown rows are the same artefact that drifted until 101 of 108 constructors
rendered blank.

Everything else in this file is a plan, not a claim.
